# Exact-copy review: second review and qualification

This change adds manual, read-only duplicate detection in **Inventory → Exact copies**.
It works with every library type and searches one explicitly chosen library. Similarity
matching, persistent indexing, cross-library comparisons and cleanup remain on the roadmap.

## Findings resolved during review

- A delayed browser poll could restore a running state after cancellation. A regression
  fails without request sequencing; the fixed view discards outdated responses.
- Large groups could retain too many paths across ten reports. Display budgets now cap
  groups, copies and total path text. Shortened groups retain their original count and
  hide their extra-copy byte total.
- Conflict responses initially used a different error shape. All three endpoints now
  use the existing API error contract and remain behind admin-token authentication.
- Missing, changed or redirected files must not become duplicate evidence. Tests cover
  those cases, mutation during hashing and directory links outside the requested scope.
- Logical copy bytes do not establish recoverable disk space. Real hard links and unknown
  link counts produce no byte-saving claim; even independent file names carry a filesystem
  caveat. There are no removal actions.
- The initial screenshot cut off the second group. The final focused capture shows both
  complete cards and the link-count explanation. Breadcrumb and disclosure icons use
  the existing icon set; cards retain the established texture and hover shadow.

## Qualification

- Warning-free Release build; **2,635 backend tests**, **212 browser tests**, **75 frontend
  unit tests** and **74 script tests** pass. Locale/type checks and generated OpenAPI pass.
- Browser cases cover 375 px and 1440 px, dark and light themes, long paths, cancellation,
  API failure, breadcrumbs and delayed-response ordering.
- Twelve production-code regression entry points pass on this Mac, native PICARD Windows,
  Quark Linux and inside Riker's running container. They use disposable generated bytes,
  real hard links and the actual read-only scanner; owned test directories are removed.
  Windows directory/symbolic-link branches remain unqualified because those tests are
  limited to Unix. Windows reports unknown link counts rather than inventing savings.
- An HTTP integration test proves that the migrated API uses inventory scope and excludes
  unfinished jobs, including a pending replacement, without changing the media.
- Documentation links and release metadata checks pass. The screenshot uses fabricated
  media and original documentation artwork, with no user library data.

## Limits and remaining work

Reads run on the server and are capped near 8 MiB/s. One scan runs at a time. The preview
accepts at most 50,000 candidates; reports live only until restart or eviction after ten
libraries. Reports are snapshots and do not authorise a later file action. Persistent,
incremental identity tracking and safe cleanup need separate implementation and tests.

The scan does not use encode slots, does not change verification placement, and does not
reserve a worker. Its disk reads can still compete with other work; no dedicated disk QoS
guarantee is claimed. CI publication must pass before deployment.
