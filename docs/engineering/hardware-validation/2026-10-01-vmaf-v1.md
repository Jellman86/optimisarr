# VMAF v1 hardware validation — 1 October 2026

The ordinary SDR upgrade uses complete VMAF v1 HD/UHD models with the existing numeric
quality floors. This is engineering acceptance, not a subjective threshold-calibration study.
See the [policy and NVIDIA feasibility decision](../../development/vmaf-v1-and-nvidia-plan.md).

## Safety and scope

All runs used isolated API databases, worker identities and scratch directories. Installed
sidecar credentials, production libraries, queues and managed containers were not changed.
The harness replaces only its generated/free-media fixtures and checks exact rollback.
Originals remain protected by all configured gates; quarantine is not a backup and purge
removes rollback ability.

Big Buck Bunny and Tears of Steel clips were checksum-verified and attributed by the
[free-media corpus manifest](../../development/media-acceptance.md). The runs used three
12-second scenes from each film plus generated SDR, VFR, offset, 10-bit and fractional-timing
fixtures. These short clips test workflows; they do not certify every title or encoder setting.

## Full-resolution controls on all four machines

Each pinned scoring executable ran six 10-bit frames at 1920×1080 and 3840×2160, with explicit
CAMBI dimensions and encoded depth. The retained [control summaries](vmaf-v1-2026-10-01/mac-controls.json)
include the exact argument arrays; corresponding files exist for
[PICARD](vmaf-v1-2026-10-01/picard-controls.json),
[Quark](vmaf-v1-2026-10-01/quark-controls.json) and
[Riker](vmaf-v1-2026-10-01/riker-controls.json).

| Control | Mean VMAF on each machine |
| --- | ---: |
| HD smooth-gradient identity | 98.796782 |
| Same gradient with deliberate quantisation/banding | 53.001611 |
| HD textured chroma identity | 100.000000 |
| Same textured content with chroma-only noise | 87.691635 |
| UHD gradient identity using the UHD model | 99.941148 |

All scores were finite and all six frames were present. CAMBI, SpEED chroma and ADM/motion
feature keys were present. Values agree to six decimal places across the tested builds; this
small control set is not a universal parity tolerance. An identity gradient need not score 100:
v1 includes a banding feature rather than being a pure pixel-identity metric.

An early control that removed chroma from a smooth synthetic gradient produced no score
penalty. It was unsuitable for proving chroma sensitivity and was replaced with textured
chroma noise. This also illustrates why VMAF alone is not proof of every kind of colour fidelity;
existing structural and colour-policy checks remain required.

## Test-first fixes and second-order review

- The live Mac RAM-disk test scopes cleanup to its own volume names. A second owned volume
  remains mounted, proving it cannot sweep a concurrently running worker's volume. Actual
  allocation, crash cleanup, successful delivery, encoder failure and cancellation pass.
- Fresh model selection probes cadence even for MKV without subtitles: inventory does not retain
  frame rate. HFR stays legacy; missing, non-positive or non-finite cadence also stays legacy.
- Model choice is persisted before adaptive selection/dispatch. Existing candidates and pre-upgrade
  adaptive choices keep legacy; automatic retries keep the recorded model. Explicit operator retry
  starts a fresh choice. Migration preserves populated history and repeated application is a no-op.
- Protocol 7 is required for gated v1 work. Both v1 model probes must produce real finite scores.
  Older workers retain compatible legacy/ungated work and cannot silently claim v1 measurement.
- Candidate dimensions and 8/10-bit depth come from actual ffprobe output. Malformed/conflicting
  depth and unexpected fixed tokens fail closed; the graph does not guess the candidate format.
- Quark's lossless H.264 subtitle fixture reports High 4:4:4 Predictive despite `yuv420p` pixels.
  QSV/VAAPI hardware decoding could not initialise it and the case timed out. A tested profile guard
  now keeps software decode plus GPU encode for formats outside the proved Baseline/Main/High path.
- Native Windows exposed SSIM log-path escaping and ExifTool Unicode/bracket filename failures.
  Reproducing unit tests plus real Windows acceptance verify the path and UTF-8 argument-input fixes.
- The source pin is authoritative: upstream's v3.2.1 archive still labels JSON logs `3.2.0`.
  Rejecting that label would reject the fixed stable build. Pins/hashes and real model probes prove
  provenance and capabilities separately.
- The Windows toolchain and matching source cache were checksum-verified; corresponding-source
  packaging completed with three archives. An expired upstream bundle now fails clearly rather
  than silently falling back to the older toolchain.

Local suites: 2,563 backend tests, 283 shared worker tests, 30 Linux host tests, 254 Swift tests,
73 Python tests and 196 Playwright tests passed. The .NET release build has zero warnings.
Swift release build succeeds with pre-existing Keychain deprecation diagnostics. Documentation,
OpenAPI, release metadata and Unraid checks pass. Both v1 smoke graphs were executed on Linux,
including their shell/filter escaping.

## NVIDIA decision and delivery boundary

RTX 4070 hardware encoding and decoding are proved above. Complete v1 measurement runs on the
CPU on the same worker. Upstream CUDA lacks the full v1 CAMBI/SpEED/new ADM/motion feature set;
no incomplete CUDA model, 8-bit replacement graph or per-card score offset is enabled.
A bounded native Windows prototype also tested CUDA decode/download followed by complete
CPU v1 on 48 HD frames. All logged features and frame scores matched the software-decode
reference within 0.000001; both scored 96.545136. CPU decode took 0.750/0.781 seconds and GPU
decode took 0.828/0.844 seconds. This small fixture showed no speed benefit, so hybrid scoring
is not enabled by default. It is neither a full-length benchmark nor evidence that GPU decode
is slower for all content. [Exact commands and timing](vmaf-v1-2026-10-01/picard-decode-benchmark.json)
are retained. Encoding remains hardware accelerated when selected.

The [feasibility/licensing decision](../../development/vmaf-v1-and-nvidia-plan.md#plan-b-practical-nvidia-acceleration)
separates permissible library use from a distributable complete FFmpeg/CUDA artifact.

Pull-request CI must still pass final server/Linux-worker images and Windows MSI install/upgrade
before merge. A published-image NVIDIA container run follows successful image publication on
PICARD under its explicit disposable-container exception. Native host results do not replace
those image checks. This change does not publish a release or upgrade production services.
